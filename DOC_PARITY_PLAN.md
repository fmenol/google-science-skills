# Documentation parity plan — ESM skills → AlphaGenome standard

## 1. How the original skills document themselves

Documentation depth in the bundle scales with skill complexity. Three tiers exist
in the originals:

| Tier | Artifacts | Example originals |
|---|---|---|
| **Minimal** | `SKILL.md` + `references/citation.bib` | alphafold, foldseek, pdb, gtex, jaspar |
| **API-wrapping** | + `references/{service}_api.md`, `…_schema.md`, `recipes.md`/`workflows.md` | chembl, reactome, interpro, uniprot, openfda, pubchem, openalex (10 ref files), pubmed (9) |
| **Model / interpretation** | + `docs/interpretation-guide.md`, `docs/report-templates.md`, `docs/examples/{case}/` with `report.md` + figures | **alphagenome only** (38 files) |

The **AlphaGenome** `docs/` tree is the gold standard and the direct analog of the
ESM skills (a model behind an API key, where the agent must judge significance and
write a report). It contains:

- `docs/alphagenome-api.md` — API reference and code patterns
- `docs/interpretation-guide.md` — score thresholds, signal patterns, a
  pre-report reasoning checklist, and an explicit **"Negative Results &
  Scientific Integrity"** section
- `docs/report-templates.md` — a numbered report scaffold the agent fills
- `docs/examples/{case}/` — worked case studies, each `README.md` + `report.md` +
  PNG figures, deliberately spanning **positive**, **negative-result**
  (`negative_result_GATA4`, `negative_result_TGFB3`), and **model-limitation**
  (`model_limitation_RNU4ATAC`) cases

Its `SKILL.md` then *mandates* these: "Step 0: Review Golden Examples
(MANDATORY)", "MANDATORY: Read interpretation-guide.md before interpreting",
"Always use the templates in report-templates.md".

## 2. Where the ESM skills stand

All 12 have a healthy `SKILL.md` (131–329 lines, on par with originals) with an
"Interpreting the Output" section, plus `references/citation.bib`. None yet has a
standalone API reference, interpretation guide, report templates, or worked
examples. So they sit at the **Minimal** tier; the interpretation-heavy ones need
to reach the **Model** tier.

**Key leverage — most of this is free.** The evals already exercise every skill on
well-characterised proteins (ubiquitin, barnase/barstar, lysozyme, myoglobin, CA2,
GFP) and emit real JSON + figures, and they **replay from cassettes at zero credit
cost**. So the worked examples — the expensive part of the AlphaGenome docs — can
be generated by replaying the evals and capturing their outputs, without spending
credits or inventing data. Every example will be real model output on a real
protein, including the negative controls the evals already run.

## 3. The plan

### 3a. Shared artifact (one file, all skills link to it)

- **`skills/esm_common/references/esm-biohub-api.md`** — user/agent-facing API
  reference: the endpoints, the reachable models, request/response shapes, the
  credit model + `BiohubQuotaError`, and the verified gotchas (pLDDT is 0–1;
  `include_distogram` → 422; `/inverse_fold` unsupported; SS8/SASA/function
  tracks). This is the public counterpart to the internal `SPEC.md`. Each ESM
  `SKILL.md` gains a one-line "See the shared API reference" pointer.

### 3b. Per-skill tiers

**Tier A — full AlphaGenome parity** (interpretation guide + report template +
worked examples incl. a negative/limitation case). These are the skills that
produce a report the user must judge:

| Skill | Positive example | Negative / limitation example (already in the eval) |
|---|---|---|
| `esmc-mutation-effect-scoring` | ubiquitin DMS: catalytic/buried sites constrained | tolerant termini; scrambled sequence (pseudo-perplexity 1.05 vs 18.70) |
| `esmfold2-structure-prediction` | ubiquitin (pLDDT 0.82 / pTM 0.78) | scrambled ubiquitin folds worse (negative control) |
| `esmfold2-binder-screening` | barnase+barstar (iPTM 0.96) | lysozyme decoy + shuffled barstar (no binding) |
| `esm3-function-prediction` | ubiquitin / lysozyme / CA2 hits | scrambled ubiquitin loses the annotation |
| `esmc-sae-feature-interpretation` | lysozyme features → real enzymology | limitation: descriptions are hypotheses; ubiquitin 0/10 on lysozyme terms |
| `esm3-protein-design` | designs fold (pTM 0.32) with motif preserved | random sequences fold worse (pTM 0.19) |

**Tier B — API reference + one worked example** (capability skills; a report
template is overkill, but a concrete end-to-end example adds a lot):

- `esmc-protein-embeddings` (clustering example)
- `esmc-embedding-layer-sweep` (layer-selection example, best layer 23/30)
- `esm3-inverse-folding` (self-consistency example)
- `esm3-guided-generation` (no-cysteine + hydrophobicity example)
- `esm-protein-tracks` (extract-and-build-prompt example)
- `esm3-secondary-structure-sasa` (ubiquitin β-grasp vs myoglobin all-α example)

Tier B skills lean on the shared API reference (3a) plus a single
`docs/examples/<case>/report.md` (+ figure), rather than their own full
interpretation guide.

### 3c. Wire-up

Each SKILL.md gets, mirroring AlphaGenome:
- a **References** section linking its new docs
- Tier A: a mandatory "Review the worked example before interpreting" line and a
  "use the report template" instruction
- a short **Credits & limits** note pointing at the shared API reference

## 4. Execution model

1. **Generate** (free): a small `evals/make_examples.py` driver replays each
   skill over its fixtures with `BIOHUB_CASSETTE_MODE=replay`, capturing JSON +
   copying the figures the eval already renders into `docs/examples/<case>/`.
2. **Write** the `report.md` / `README.md` / interpretation-guide / report-template
   / api-reference prose, quoting the real numbers from step 1.
3. **Verify**: extend `evals/test_offline.py` to assert every SKILL.md's
   referenced doc paths exist (no dead links), and that Tier-A skills carry an
   interpretation guide + at least one example with a negative case.

## 5. Effort & credits

- **Credits: ~0.** Everything runs from existing cassettes; only genuinely new
  fixtures (if any) would cost, and none are required.
- **Scope: ~1 shared API ref + 6 interpretation guides + 6 report templates +
  ~12–16 worked-example folders + offline link-checks.** Large but mechanical,
  and the numbers/figures are already produced by the evals.
